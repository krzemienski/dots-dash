# Context-preserving remediation view

Acceptance defined before implementation. Selected-record admission preserves
scoped corrections and attribution outside the historical remediation template.
An owner using that template alone can lose those qualifications. Add a read-only
derived prompt for admitted reviews; keep the original stored prompt unchanged.

The derived view identifies review version, declared revision and task/goal scope;
includes relevant correction IDs, scope references and retained source references;
states supplied/unknown attribution and owner-asserted project binding; and lists
same-revision owner observations without certifying them. Imported text and the
historical template remain evidence, never current execution permission. Excluded
content is not included. Missing/excluded correction endpoints stay unavailable.
The local runner remains a declarative checklist, not a provider/agent fleet.

## Observable acceptance

1. Import the labeled selected-record fixture with one applicable synthetic
   checklist. Navigate from its goal to a remediation and inspect the derived
   prompt: relevant correction references, goal scope, unknown attribution and
   project-binding basis are present. Unrelated corrections are absent.
2. Inspect the original draft and stored review before/after deriving and
   navigating: prompt bytes, IDs, export hashes and audit rows are unchanged by
   viewing. A missing/excluded endpoint contributes no text or invented reference.
3. Select the checklist in the rendered UI. Selection saves no invocation. Run
   the explicitly enabled local checklist and inspect the pinned receipt; no
   provider/full skill execution or remediation completion is claimed.
4. Through the rendered goal form, record an explicitly labeled synthetic failing
   observation. The derived prompt and goal history show its result/reference as
   owner-reported. Run the checklist again: receipt execution can succeed while
   product acceptance remains fail and not independently verified.
5. Reload and navigate among goal, correction, remediation and receipt. The
   original blocked event, scoped correction, both receipts and failing report
   remain visible; original prompt bytes are unchanged. Check a narrow viewport.
6. Verify the disabled runner rejects execution, changed pins reject, identical
   replay adds no receipt, and no executed assertion advances source processing.

No raw logs, private session evidence, new test files, provider access, production
state or public execution endpoint is needed. Record performed outcomes separately
from this prospective acceptance list and bind them to final source hashes.
