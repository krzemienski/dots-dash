# Skill use review

Turn a relevant skill into an accountable contribution to the requested outcome.
A catalog match is not evidence that guidance was read, applied or effective.

1. Bound discovery to the authorized roots and task. Start with skill filenames
   and plugin-manifest metadata; record exclusions, denied paths, symlinks and
   unfinished cursors privately. Do not follow links into exclusions, retry a
   denial through another route, or infer complete coverage from a finished page.
   Compare exclusion names case-insensitively. Read only the relevant located
   entrypoints and skill-owned references; discovery is not a reason to ingest
   sessions, private assistant instructions or credential stores.
2. Choose the smallest useful set by task outcome and description. Record the
   exact source/hash and why it applies; keep same-name variants distinct.
   Identical file hashes establish duplicate bytes, not equal dependencies,
   activation or ownership. If a specialized capability is unavailable, keep
   that gap visible instead of inventing a tool or installing one implicitly.
3. Record available, selected, read, applied and outcome-verified separately,
   using the [evidence record](../../../docs/SKILL_WORKFLOW.md#evidence-record).
   Reading is evidenced by the file/version read; application needs a concrete
   decision or artifact; verification needs an observed result and its limits.
   Manual use of guidance is not provider invocation. A local checklist receipt
   proves only that checklist's execution, not execution of an entire skill.
4. Improve only project-owned guidance within current writer authorization.
   Filesystem ownership alone does not authorize edits. Treat installed/vendor
   copies as read-only. Use available Skill Creator guidance for authoring; if
   it is unavailable, record that gap. Change the smallest trigger, instruction
   or reference supported by observed feedback. Preserve unrelated behavior.
5. Before accepting a revision, exercise realistic requests that should route
   to it and near misses that should not. Check the resulting action, exclusions
   and stopping point, not merely matching words. Run the available structural
   validator and applicable checks; label a manual routing exercise as such.
   Use actual authorized workflow evidence when available, bound to its source
   revision. Do not relabel historical results as a new execution.
6. Append the result, unresolved limits and next improvement to the existing
   project evidence ledger. Keep machine paths, inventories and private skill
   content local; publish only sanitized reusable guidance when authorized.
   This process creates no scheduler, watcher, host configuration change or
   permission to run a provider, send messages, merge or deploy.
